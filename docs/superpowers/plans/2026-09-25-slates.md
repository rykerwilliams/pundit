# Slates — phase A plan

Spec: `docs/superpowers/specs/2026-09-25-slates-design.md`. Phase A is the
whole feature; §S10 says why there is no typed editor.

Each task ends green (`cargo fmt --all --check`, `cargo clippy --workspace
--all-targets -- -D warnings`, the tests named in the task) and is one commit.
The coach is using the app on this machine, so every cargo call stays under
`flock /tmp/claude-1000/cargo.lock nice -n 19`.

## Task 1 — the record, in core

`crates/pundit-core/src/project.rs`, `store.rs`.

- `Slate { id, source_index, in_seconds, out_seconds: Option<f64>, name, tags }`
  — a new struct, so **no field-level defaults** (a missing field is a
  malformed file).
- `Project.slates: Vec<Slate>` with a field-level `#[serde(default)]`.
- `Clip.slate_id: Option<Uuid>` with a field-level `#[serde(default)]` (§S3).
- `CURRENT_FORMAT_VERSION = 12`; floor stays 7.
- `Project::slates_sorted()` → `(source_index, in_seconds)` (§S2: there is no
  `sort_index`, and this is the only order that means anything).

**And every `Clip` struct literal in core, harness and media tests** — `Clip`
has no `Default` (its fields are required, deliberately) and `#[serde(default)]`
does nothing for a Rust literal, so ~25 sites across 20 files gain
`slate_id: None`. The diff is large and entirely mechanical; the compiler finds
every one.

**Tests** (`crates/pundit-core/tests/project_format.rs`): a v12 file
round-trips with slates and a clip carrying `slate_id`; `a_v11_file_loads_under_the_current_version`
beside the existing ones, asserting the `project.json.v11` backup. The v10 test
stops pinning the literal version it saves as — that is the one number a bump
always changes.

## Task 2 — the source list, and the undo hole

`project.rs`, `crates/pundit-core/src/undo.rs`.

- `source_is_referenced` gains a slate clause — a source a slate points at
  **cannot be removed** (§S7). Update the two strings that enumerate the kinds:
  `project.rs`'s and `UserError::SourceReferenced`'s ("still used by a clip, a
  match event or a highlight" → "…, a highlight or a slate").
- `move_source` / `remove_source` remap `slate.source_index` beside the three
  loops already there.
- `UndoAction::EditSlates` joins `stale_snapshot` — **and that closure becomes
  an exhaustive `match` returning `bool`**, because as a `matches!` it silently
  admits every future record type (§S7). While making it exhaustive: rename it
  for what it tests (`holds_stale_indices`), group the two arms that hold no
  source index, and give `DeleteClip` its own arm with a comment — a bare
  `DeleteClip(_) => false` would read as "a delete survives a source change",
  which is the opposite of what the `partition` two lines below does with it.
- **A third user-facing string** enumerates the kinds and the plan first missed
  it: `app.slint`'s remove-button tooltip ("Used by a clip, a match event or a
  highlight. Delete those first."), which is what the coach actually reads when
  the ✕ greys out. Plus six doc comments that enumerate (`SourceReferenced`,
  `source_is_referenced`, `remove_source`, `purge_for_source_change`,
  `purge_history_for_source_change`, and `tests/sources.rs`'s header).

**Tests** (`crates/pundit-core/tests/sources.rs`): removing a source a slate
points at is refused — the error carries the source index, not the kind, so the
test asserts the refusal, and the *message* listing "a slate" is checked where
that string lives; moving a source remaps slate indices;
**the one the compiler cannot catch** — mark slates on a source, move that
source, undo an unrelated edit, and the slates still point at the same file.

## Task 3 — the commands

`crates/pundit-app/src/bus/` (a new `slates.rs`, plus `mod.rs`).

- `Command::{MarkSlateIn, MarkSlateOut, EditSlate, DeleteSlate, ShootSlate}`.
  The two marks carry a caller-captured `(source_index, source_seconds)` (the
  bus contract). **`ShootSlate` carries `{ id, zoom }` and no position** — the
  in point is stored, not read from the playhead, which is `EditMatchEvent`'s
  own reasoning; the `zoom` is what `RecordingLog::new` seeds the log with.
  `EditSlate` carries a `core::undo::SlateEdit { Name(String), Tags(Vec<String>) }`,
  the shape `ClipEdit` and `HighlightEdit` already use.
- **`UserError::Slate(String)`**, and its arm in `is_notice()`: a refusal can
  land mid-recording (marking is on the allow-list), and a modal over a live
  take would swallow the transport keys — `UserError::Scoreboard`'s doc says
  exactly this. Reusing `Scoreboard` would be a lie in the type name.
- `MarkSlateIn` takes the `source_index >= source_videos.len()` guard that
  `tag_match_event` and `set_highlight_key` both have, or a slate can be stored
  on a source that is not there and Task 5's row panics indexing it.
- **Only the two marks are on the recording allow-list.** `ShootSlate`,
  `EditSlate` and `DeleteSlate` are not, and the UI greys them while recording,
  because the bus's refusal is only an `eprintln!`.
- `bus/clips.rs`'s `replay` — the exhaustive `match` where undo is *applied* —
  gains an `EditSlates` arm beside `EditMatchEvents` and `EditHighlights`.
- One sentence on the `slates` field: **the stored order is the marked order**,
  and `MarkSlateOut` ("the most recent open slate on this source") depends on
  it. `slates_sorted` is for reading only; nothing sorts the stored `Vec`.
- `MarkSlateIn` creates an open slate; `MarkSlateOut` closes the most recent
  open slate **on that source**, refusing with a reason when there is none.
- `MarkSlateIn` / `MarkSlateOut` join the recording allow-list in
  `Bus::command`, beside `TagMatchEvent` and `SetHighlightKey` (§S4).
- Every edit goes through one `edit_slates` snapshot-undo funnel, as
  `edit_match_events` and `edit_highlights` do.
- `Event::ProjectChanged` carries the new state; no new event type.

**Tests** (`crates/pundit-harness/tests/slates.rs`, new): `i` then `o` produces
one closed slate at the given times; `o` with nothing open refuses and stores
nothing; marking works **while recording**; an edit and a delete are undoable.

## Task 4 — shooting

`bus/slates.rs`, `bus/recording.rs`.

**One entry point, not a sequence from outside** (§S5): `start_recording` gains
`start: Option<(usize, f64)>` and `slate: Option<Uuid>`; `toggle_recording`
passes `None, None`. The seek happens **inside**, after `capture_sources`
succeeds — because `NoCamera` comes from `resolve_camera` there, *not* from
`can_record`, so an outside sequence would move the player and then refuse on a
camera-less machine. It also avoids widening two private functions.

`Active` carries the slate id; `finish_recording` applies the slate's `name` and
`tags` to the new clip and sets `slate_id`, **in the save it already does** —
`PendingClip` stays `Copy` and `add_recorded_clip` stays pure. Two mechanical
details, so they are not met as a borrowck fight: `add_recorded_clip` returns
`&Clip`, so the fields are applied through `clips.last_mut()` straight after,
and the slate's name and tags are **cloned out before** the `&mut project`
borrow. A slate deleted while the take ran inherits nothing; an aborted take
leaves the slate unshot, which is automatically right because "shot" is derived
from the clips.

An **empty** slate name leaves the clip's generated `"2-01:02:05"` alone.

**Tests** (harness): a preview open refuses the shoot and leaves the player
where it was; a pending skip burst does not move the clip's start off the in
point; the clip carries the slate's name, tags and `slate_id`; an unnamed slate
leaves the generated name.

## Task 5 — the UI

`crates/pundit-app/ui/app.slint`, `main.rs`.

- A **Slates** section in the sidebar above the clips: one row per slate in
  `(source_index, in_seconds)` order, showing the range (`14:05–14:40`, or
  `14:05–` while open), which video when there is more than one, the name, the
  tags, and whether it has been shot (`clips.iter().any(slate_id == …)`).
- **The section is hidden entirely when there are no slates**, which is every
  existing project, and its list takes a fixed maximum height. The sidebar is
  240 px wide with two `ListView`s already competing for vertical stretch; a
  third that always shows would shrink the clip list on every project for a
  feature not in use. The row is two lines (range and video, then name and
  tags), with Record and delete in the row's menu as the clip row does it —
  not four buttons in 240 px.
- Row actions: **Record** (greyed while recording), delete, and select-to-edit —
  name and tags in the shape the clip inspector already uses. **Its `editing`
  joins the window's `text-editing` fold in this same commit**, or typing a
  slate's tags fires every letter shortcut, the new `i`/`o` included. The keys
  also guard `!event.repeat`.
- `show_project` gains: `show_slates`, a "drop a selection whose slate is gone"
  clause mirroring the clip rule (an undone delete is exactly when it bites), a
  `SlateRow` carrying the source's display name, and — since the row edits — an
  `editing-slate-id` following the `editing-clip-id` rule, because `for` reuses
  its items by index.
- `i` / `o` in the key handler, gated on the existing `can-tag` (§S4), sending
  the displayed frame's source time from `shown_position`.
- `tag_suggestions` takes a `&[String]` vocabulary instead of `&[TagSummary]`
  (a slate has no `clip_count` or `total_seconds`), fed by a new
  `tag::tag_vocabulary(project)`. One call site, `tests/tags.rs` updated, and
  the tag **overview** keeps `tag_summaries(&project.clips)` untouched (§S8).

**Tests**: `crates/pundit-app/tests/` for the row's pure formatting (the range
string, the open case, the shot flag); the rest is covered over the bus.
