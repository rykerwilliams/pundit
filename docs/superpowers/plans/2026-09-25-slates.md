# Slates — phase A plan

Spec: `docs/superpowers/specs/2026-09-25-slates-design.md`. Phase A is the
whole feature; §S10 says why there is no typed editor.

Each task ends green (`cargo fmt --all --check`, `cargo clippy --workspace
--all-targets -- -D warnings`, the tests named in the task) and is one commit.
The coach is using the app on this machine, so every cargo call stays under
`flock /tmp/claude-1000/cargo.lock nice -n 19`.

## Task 1 — the record, in core

`crates/pundit-core/src/project.rs`, `store.rs`.

- `Slate { id, source_index, in_seconds, out_seconds: Option<f64>, name, tags }`
  — a new struct, so **no field-level defaults** (a missing field is a
  malformed file).
- `Project.slates: Vec<Slate>` with a field-level `#[serde(default)]`.
- `Clip.slate_id: Option<Uuid>` with a field-level `#[serde(default)]` (§S3).
- `CURRENT_FORMAT_VERSION = 12`; floor stays 7.
- `Project::slates_sorted()` → `(source_index, in_seconds)` (§S2: there is no
  `sort_index`, and this is the only order that means anything).

**Tests** (`crates/pundit-core/tests/project_format.rs`): a v12 file
round-trips with slates and a clip carrying `slate_id`; `a_v11_file_loads_under_the_current_version`
beside the existing ones, asserting the `project.json.v11` backup.

## Task 2 — the source list, and the undo hole

`project.rs`, `crates/pundit-core/src/undo.rs`.

- `source_is_referenced` gains a slate clause — a source a slate points at
  **cannot be removed** (§S7). Update the two strings that enumerate the kinds:
  `project.rs`'s and `UserError::SourceReferenced`'s ("still used by a clip, a
  match event or a highlight" → "…, a highlight or a slate").
- `move_source` / `remove_source` remap `slate.source_index` beside the three
  loops already there.
- `UndoAction::EditSlates` joins `stale_snapshot` — **and that closure becomes
  an exhaustive `match` returning `bool`**, because as a `matches!` it silently
  admits every future record type (§S7).

**Tests** (`crates/pundit-core/tests/sources.rs`): removing a source a slate
points at is refused and names the slate; moving a source remaps slate indices;
**the one the compiler cannot catch** — mark slates on a source, move that
source, undo an unrelated edit, and the slates still point at the same file.

## Task 3 — the commands

`crates/pundit-app/src/bus/` (a new `slates.rs`, plus `mod.rs`).

- `Command::{MarkSlateIn, MarkSlateOut, EditSlate, DeleteSlate, ShootSlate}`,
  each carrying its caller-captured `source_index` / `source_seconds` where it
  needs one (the bus contract: never queried in the handler).
- `MarkSlateIn` creates an open slate; `MarkSlateOut` closes the most recent
  open slate **on that source**, refusing with a reason when there is none.
- `MarkSlateIn` / `MarkSlateOut` join the recording allow-list in
  `Bus::command`, beside `TagMatchEvent` and `SetHighlightKey` (§S4).
- Every edit goes through one `edit_slates` snapshot-undo funnel, as
  `edit_match_events` and `edit_highlights` do.
- `Event::ProjectChanged` carries the new state; no new event type.

**Tests** (`crates/pundit-harness/tests/slates.rs`, new): `i` then `o` produces
one closed slate at the given times; `o` with nothing open refuses and stores
nothing; marking works **while recording**; an edit and a delete are undoable.

## Task 4 — shooting

`bus/slates.rs`, `bus/recording.rs`.

`ShootSlate` is, in this order (§S5): `can_record()` → `reset_skip()` →
`load(source, in_seconds)` → `start_recording`. `Active` carries the slate id;
`finish_recording` applies the slate's `name` and `tags` to the new clip and
sets `slate_id`, **in the save it already does** — `PendingClip` stays `Copy`
and `add_recorded_clip` stays pure.

An **empty** slate name leaves the clip's generated `"2-01:02:05"` alone.

**Tests** (harness): a preview open refuses the shoot and leaves the player
where it was; a pending skip burst does not move the clip's start off the in
point; the clip carries the slate's name, tags and `slate_id`; an unnamed slate
leaves the generated name.

## Task 5 — the UI

`crates/pundit-app/ui/app.slint`, `main.rs`.

- A **Slates** section in the sidebar above the clips: one row per slate in
  `(source_index, in_seconds)` order, showing the range (`14:05–14:40`, or
  `14:05–` while open), which video when there is more than one, the name, the
  tags, and whether it has been shot (`clips.iter().any(slate_id == …)`).
- Row actions: **Record**, delete, and select-to-edit — name and tags in the
  shape the clip inspector already uses.
- `i` / `o` in the key handler, gated on the existing `can-tag` (§S4), sending
  the displayed frame's source time from `shown_position`.
- `tag_suggestions` is fed the union of clip and slate tags; the tag
  **overview** is untouched (§S8).

**Tests**: `crates/pundit-app/tests/` for the row's pure formatting (the range
string, the open case, the shot flag); the rest is covered over the bus.
